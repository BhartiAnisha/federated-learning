# Federated Learning (FedAvg) on Healthcare, Finance and IoT tabular data

Everything here was executed; all numbers in `results/` and `figures/` come from those runs.
PyTorch could not be installed in this environment, so the MLP (manual back-propagation, verified against numerical
gradients to ~1e-10), Adam/SGD, FedAvg and FedProx are implemented in NumPy.

## Algorithm

**Model.** Binary MLP (ReLU hidden layers, sigmoid output, weighted BCE + L2 weight decay, optional dropout).
Logistic regression is the same code with no hidden layer.

**FedAvg.** In round t the server picks m = round(C·K) clients, sends them the global weights w_t, each client
runs E local epochs of mini-batch Adam/SGD on its own records, returns w_{t+1}^{(k)}, and the server sets

    w_{t+1} = Σ_k (n_k / N) · w_{t+1}^{(k)},     N = Σ_{k in S_t} n_k

**FedProx.** Same loop, but each local gradient gets an extra term μ(w − w_t).

### Pseudocode

```
Server executes:
  initialise w_0;  best_loss ← ∞;  bad ← 0
  for t = 1 … R:
      S_t ← random subset of m = max(1, round(C·K)) clients
      payload ← serialise(w_{t-1})                       # float32 bytes, counted as download
      for each client k in S_t (in parallel):
          (w_k, n_k) ← ClientUpdate(k, payload, lr_t)    # w_k serialised, counted as upload
      w_t ← Σ_k (n_k / Σ_j n_j) · w_k                    # FedAvg
      (val_loss, val_acc, val_auc) ← Evaluate(w_t, validation set)
      if val_loss < best_loss: best_loss ← val_loss; save checkpoint(w_t); bad ← 0
      else: bad ← bad + 1;  if bad ≥ patience: break
  return best checkpoint                                 # test set evaluated once, after this

ClientUpdate(k, w, lr):                                  # runs on the client; raw data never leaves
  w_global ← w
  for epoch = 1 … E:
      for each mini-batch B of local data D_k:
          g ← ∇ weighted_BCE(w; B) + weight_decay·w
          if FedProx: g ← g + μ (w − w_global)
          w ← optimizer_step(w, g, lr)                   # Adam or SGD+momentum, state reset each round
  return (w, |D_k|)
```

**Privacy statement.** This is plain FL: the server never receives raw records, only weight vectors. There is **no**
secure aggregation, differential privacy or encryption, so no formal privacy guarantee is claimed (model updates can
still leak information about client data).

## Protocol (leakage control)

- Exact duplicate records (features + label) removed before splitting; IDs are not used as features.
- Stratified 70/15/15 train/validation/test split per seed. Imputer, scaler and one-hot encoder are fit on **train only**.
- Hyper-parameters chosen by random search (30 configs + defaults) on the **validation** set of seed 0 using
  score = val accuracy + val ROC-AUC. The test set is used once per run, after model selection.
- Threshold = default 0.5 (not tuned).
- 5 seeds (0-4); the seed controls split, partition, client sampling and weight initialisation. SD is the sample SD
  (ddof=1) across seeds; CIs are t-based (n=5, so wide).
- Communication = the float32 payloads actually serialised (4 bytes × params × participating clients × rounds, both
  directions). Headers, compression, encryption and retransmissions are NOT included.
- Memory = `tracemalloc` peak of Python/NumPy allocations, not process RSS. Timings are from a single-process
  simulation on a shared 2-core CPU, not real network latency.
- Non-IID = per-class Dirichlet label skew, α = 0.5 (moderate) and 0.1 (strong), K = 10.
- Client-level accuracy = global model evaluated on each client's own training records (no separate local test sets).

## Caveats and limitations

1. **94% was not reached on any dataset.** It is borderline on Hospital and clearly unattainable on Bank, where a
   majority-class predictor already scores 88.5% and FedAvg barely exceeds the centralized models. I did not tune on
   the test set or change the task to chase it.
2. **Hospital dedup is aggressive.** Many breast-cancer records have identical integer feature vectors, so removing
   exact duplicates cuts 699 → 463 rows (test set only 70 samples; one error ≈ 1.4 pp). Results are not comparable
   to published figures on the full 699-row file.
3. **IoT dedup removed 62% of rows** (identical temp/minute/label readings). The task (predict In/Out from
   temperature + timestamp) is my assumption; the file has no stated target. FedAvg ran all 60 rounds
   (no early stop), so it may be under-trained.
4. **The IoT FedAvg > centralized MLP gap is not a fair FL-beats-centralized result:** the centralized baseline was
   capped at 30 epochs with early stopping, whereas FedAvg had up to 60 rounds × 3 local epochs.
5. Bank `duration` is only known after the call; the "with duration" numbers are optimistic. Use `bank_nodur` for a
   deployable setting.
6. Tuning chose `local_epochs=1` for Hospital; the ablation shows 3 epochs scoring higher on test (0.9486). That is
   noted but **not** used to re-select the configuration, since that would be test-set tuning.
7. At K = 50 on Bank, runs hit the 80-round cap without converging; on Hospital, 50 clients hold ~6 records each.
8. With 5 seeds, paired tests have low power and no multiple-comparison correction was applied. FedProx μ = 0.01 was
   not tuned and was indistinguishable from FedAvg in these IID settings.
9. No client dropout/failure was simulated (successful clients per round = participating clients).
10. Non-IID: Bank and IoT degrade under strong skew (see Table 4); Hospital does not show a measurable drop, but its
    test set is tiny. Robustness is not claimed.
